账本 `unaccounted_ns=0`，因此该结果不是加总错误。

层级 GPU event 显示第1层约3.61 ms，其余层大多约2.0–2.5 ms；2–32层的逐层执行约占68 ms，基本对应 `finish→remaining prefill submission`。这说明当前 fallback 慢点主要是**resumable layer-by-layer 执行路径本身**，而不是单纯 planner 或 winner H2D：

1. FinalCommit 拒绝后仍执行完整 dense continuation，因此选择、ready检查和planner开销全部已发生；
2. continuation使用逐层 resumable 调度，每层有独立 active-row/状态处理，不能直接等同于原生 Prefix fused dense；
3. 当前运行的 active rows 是完整目标行（`active_equals_target=true`），但仍不能据此证明和原生 dense 数值完全等价；
4. 当前层事件缺少可靠的 host launch gap 字段，不能把 event envelope 的全部差额归因于 GPU kernel或Python。

## 决策

P0 已达到“patch provenance、r=1 correctness、成本文件存在且真实”的诊断门；P1 已定位到 fallback layer path，但**P1 尚未通过性能/等价性门**。下一步应在保持正确 attention 数值路径的前提下，对逐层 continuation 做单改动配对：关闭高扰动 instrumentation、测 host launch gap、比较一次性 dense remainder 与逐层提交，并逐层核对 hidden/residual/logits。未经 `relative-L2≤1e-4` 与完整 TTFT 配对验证，不启用 native continuation 优化。

本结果仍不授权：多 Source 结论、SparseX/QCFuse 集成、多 Segment、Qwen、正式 Profile、runtime qualification 或 locked test。
